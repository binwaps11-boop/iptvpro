   &eth0 = the CPU/conduit (rgmii-id, fixed-link 1000/full).

   PORT MAPPING (official): eth0 = CPU/conduit only; wan = standalone DSA port;
   lan1..lan4 = DSA ports bridged into br-lan. Matches the user's requirement.

5) ABOUT "qca8k mdio.0:00: No ports node specified in device tree!"
   - The EXTERNAL ports node IS present (as `ethernet-ports` above) — that is why
     lan1-4/wan/cpu enumerate and bridge correctly. The qca8k driver accepts both
     `ports` and `ethernet-ports`.
   - The INTERNAL PHY `mdio` node IS also present (phy@0..phy@4).
   - So nothing is actually missing from the DTS. The message is a NON-FATAL
     qca8k notice emitted on the MDIO-attached probe path; it does NOT affect DSA
     or VLAN (proven on-device: dsa_core+tag_qca+qca8k load, ports map to br-lan,
     wan separate, bridge vlan works when vlan_filtering=1).
   - Therefore NO DTS edit is made for it (a blind ports/mdio edit would risk
     breaking a working, correct, upstream DTS). If a future need arises it will
     be done only against the real captured DTS (/etc/kt412-dts.txt) with a diff.

6) lan3 STABILITY (not a DTS/driver problem)
   - The earlier "smartap-wd: port lan3 frozen -> bounce link" was OUR watchdog's
     bad heuristic (idle port = zero bytes != frozen). That port-bounce logic is
     REMOVED from /root/smartap-watchdog.sh. Zero traffic is never treated as a
     fault now.
   - EEE (Energy-Efficient-Ethernet) is disabled on the DSA ports via
     /etc/hotplug.d/net/20-kt412-eee (qca8k EEE can cause gigabit link flap).
