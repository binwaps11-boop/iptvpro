# IPTV Pro — نظام بث IPTV بأدوار (Admin / عملاء) شبيه Jellyfin

نظام كامل لبثّ **القنوات المباشرة + الأفلام + المسلسلات (بالحلقات)** بمعمارية خادم/عميل:

- **لوحة الإدارة** (`/admin`) — المسؤول وحده: يضيف مصادر IPTV (M3U / Xtream)، يدير العملاء
  (إنشاء اشتراكات + حدّ أجهزة + مدة)، ويضبط البروكسي/VPN والإعدادات، ويرى الإحصائيات.
- **بوابة العملاء** (`/`) — العملاء: **مشاهدة فقط** بعد تسجيل الدخول (لا يمكنهم إضافة أي مصدر).
- **Shared Relay**: نفس القناة تُسحب مرة واحدة من المزوّد وتُوزَّع على كل الأجهزة (مضاد للتقطيع).
- قابل للنشر على **VPS كموقع** يُفتح من المتصفح بلا أي تطبيق.

> مكتفٍ ذاتياً: Node.js فقط، **بدون أي حزم npm** ولا قاعدة بيانات خارجية (يُخزَّن في `config.json`).

---

## ⚡ التشغيل السريع (محلياً)

المتطلب: [Node.js](https://nodejs.org) 18+.

```bash
cd desktop
ADMIN_PASSWORD='كلمة-مرور-قوية' node server.js
```

النظام يعمل على **منفذين منفصلين**:
- **بوابة العملاء:** `USER_PORT` (افتراضي **221**) — العملاء يشاهدون فقط.
- **لوحة الإدارة:** `ADMIN_PORT` (افتراضي **331**) — `/admin` متاحة من هذا المنفذ فقط.

> ⚠️ المنفذان 221/331 محجوزان (<1024) ويتطلبان root محلياً. للتجربة المحلية بدون root:
> ```bash
> USER_PORT=2221 ADMIN_PORT=3331 ADMIN_PASSWORD='قوية' node server.js
> # العملاء: http://localhost:2221/    الإدارة: http://localhost:3331/admin
> ```
> (سكربت `deploy/install.sh` يمنح الخدمة صلاحية المنافذ المحجوزة تلقائياً على VPS.)
>
> إن لم تضع `ADMIN_PASSWORD`, ستكون كلمة المرور الافتراضية `admin` (سيُطلب منك تغييرها فوراً).

## 🧑‍💼 خطوات الاستخدام

**في لوحة الإدارة:**
1. **أضف مصدر IPTV** من قسم «📥 مصادر IPTV» — يُفضّل تبويب **Xtream** للحصول على الأفلام والمسلسلات:
   - مثال لرابط `http://ms.example.com/get.php?username=USER&password=PASS&...`
     → السيرفر `http://ms.example.com`، المستخدم `USER`، كلمة المرور `PASS`.
2. **أنشئ عملاء** من قسم «👥 العملاء»: اسم مستخدم + كلمة مرور + المدة (أيام) + حد الأجهزة.
   يمكنك لاحقاً: تجديد +30 يوم، إيقاف/تفعيل، أو حذف العميل.
3. اضبط **البروكسي/VPN** و**Headers** عند الحاجة (قسم الإعدادات).

**العميل:** يفتح رابط الموقع → يسجّل الدخول ببياناته → يشاهد القنوات/الأفلام/المسلسلات فقط.
يظهر له اسمه والأيام المتبقية، ويُفرض عليه حدّ الأجهزة المتزامنة الذي حدّدته له.

## 🌍 النشر على VPS (موقع بلا تطبيق)

### الطريقة الأسهل — أمر واحد (Ubuntu/Debian)

من جهازك ادخل على السيرفر ثم نفّذ:
```bash
ssh root@SERVER_IP

apt update && apt install -y git curl
git clone <REPO_URL> /opt/iptvpro
cd /opt/iptvpro/desktop
sudo ADMIN_PASSWORD='كلمة-مرور-قوية' bash deploy/install.sh
```
السكربت يثبّت Node ويُعدّ خدمة دائمة (systemd) على منفذين ويفتحهما في الجدار الناري:
- 👥 العملاء: `http://SERVER_IP:221/`
- 🔐 الإدارة:  `http://SERVER_IP:331/admin`

**مع دومين و HTTPS تلقائياً** (وجّه الدومين A-record إلى السيرفر أولاً):
```bash
sudo ADMIN_PASSWORD='كلمة-قوية' DOMAIN=tv.example.com EMAIL=you@mail.com bash deploy/install.sh
```
ينصّب Nginx + شهادة Let's Encrypt تلقائياً، فيصبح الموقع `https://tv.example.com`.

### أو عبر Docker
```bash
cd /opt/iptvpro/desktop
ADMIN_PASSWORD='كلمة-قوية' docker compose -f deploy/docker-compose.yml up -d --build
```
البيانات تُحفظ في volume باسم `iptvpro_data`.

### أوامر التشغيل
```bash
journalctl -u iptvpro -f          # متابعة السجل
systemctl restart iptvpro         # إعادة تشغيل
cd /opt/iptvpro && git pull && systemctl restart iptvpro   # تحديث
```

> **HDMI/شبكة:** أي جهاز (تلفزيون/جوال/لابتوب) يفتح الرابط في المتصفح ويشاهد — ومن المشغّل
> زر «⛶ ملء الشاشة» لعرضه على شاشة التلفزيون عبر HDMI.

## 🛡️ نظام VPN Egress الإنتاجي (WireGuard/OpenVPN + Split-tunnel + Kill Switch)

نظام يوجّه **طلبات IPTV فقط** عبر VPN في دولة مسموحة (مثل المكسيك)، ويبقي SSH/الإدارة على IP
السيرفر، مع **Kill Switch** (لا تسريب عند انقطاع VPN)، **watchdog** (إعادة اتصال + fallback)، وكل
الأسرار في `.env` (لا مفاتيح داخل الكود).

### التثبيت والتشغيل
```bash
cd /opt/iptvpro/desktop
cp .env.example .env && nano .env          # اضبط VPN_COUNTRY والأسرار
sudo bash vpn/install-vpn.sh               # يثبّت الأدوات + خدمة systemd (تعمل بعد الإقلاع)
sudo nano /etc/iptvpro/vpn/MX.conf         # ضع ملف WireGuard المكسيكي هنا (فيه AllowedIPs=0.0.0.0/0)
sudo systemctl restart iptvpro-vpn         # تشغيل
```

> **أين تضع المفاتيح؟** ملف WireGuard كاملاً (وفيه المفتاح الخاص) في `/etc/iptvpro/vpn/MX.conf`
> — **خارج المستودع** (لا يُرفع إلى Git). `.env` للأسرار الأخرى وهو مُتجاهَل في Git أيضاً.

### الفحص (نتائج حقيقية)
```bash
sudo bash vpn/verify.sh
```
يطبع: حالة VPN · IP السيرفر مقابل IP التطبيق · الدولة · مسار الحزمة · أكواد HTTP على مزوّدك
(200/403/429/1020) · اختبار Kill Switch · الحالة بعد كل ذلك.

### تغيير الدولة
- **فوري (ad-hoc):** `sudo bash vpn/vpnctl.sh up US`
- **دائم:** عدّل `VPN_COUNTRY=US` في `.env` ثم `sudo systemctl restart iptvpro-vpn`
- ضع ملف الدولة الجديدة باسمها: `/etc/iptvpro/vpn/US.conf` (أو `US.ovpn` لـ OpenVPN).

### إضافة مزوّد VPN جديد
ضع ملف إعداده فقط باسم الدولة في `VPN_CONF_DIR`:
- WireGuard → `<CC>.conf` ، OpenVPN → `<CC>.ovpn` (واضبط `VPN_TYPE`).
لا تغيير في الكود — النظام يلتقط الملف حسب `VPN_COUNTRY`.

### Cloudflare (حلول قانونية فقط)
- **لا** نكسر حماية Cloudflare. إن كان الحجب من مزوّد خارجي لا تملكه → الحل القانوني الوحيد
  هو IP خروج نظيف من دولة مسموحة (هذا النظام) أو مراسلة المزوّد.
- **إن كنت تملك Cloudflare Zone** (لبوّابتك مثلاً): في Security → WAF أضف قاعدة مخصّصة
  `(ip.src eq <VPN_EGRESS_IP>)` → Action: **Skip/Allow**؛ واخفض false positives بضبط
  Security Level إلى Medium وإنشاء استثناء WAF لمسارات الـ API المشروعة.

### الاستقرار
- `Restart=always` + watchdog كل `VPN_HEALTH_INTERVAL` ثانية → auto‑reconnect.
- fallback تلقائي إلى `VPN_FALLBACK_COUNTRY` إن فشلت الأساسية.
- سجلّ واضح: `journalctl -u iptvpro-vpn -f` و `/var/log/iptvpro-vpn.log`.
- يعمل بعد إعادة تشغيل السيرفر (الخدمة enabled).

## 🚀 الأداء ومحدوديّات «آلاف الأجهزة» (بصراحة)

- **Shared Relay** (مُختبَر): 100 جهاز يطلبون نفس الجزء = **سحبة واحدة** من المزوّد. هذا يلغي
  التقطيع ويحمي اشتراكك عند مشاهدة الجميع نفس القناة.
- **حدود فيزيائية لا يحلّها أي كود:**
  - **عرض النطاق:** سيرفر بشبكة 1 جيجابت ≈ **~250 جهاز** على قناة HD واحدة (4 ميجابت/ث).
    لـ 1000–2000 جهاز: استخدم **سيرفر بشبكة 10G**، أو **قلّل الجودة**, أو **وزّع على عدة سيرفرات**.
  - **حدّ المزوّد:** اشتراكك له حدّ اتصالات متزامنة؛ لا يمكن سحب آلاف القنوات *المختلفة* من اشتراك واحد.

## 🌎 VPN/بروكسي لتجاوز الحظر الجغرافي

من لوحة الإدارة ← الإعدادات ← «بروكسي/VPN»: فعّل التوجيه وأدخل بروكسي **HTTP** أو **SOCKS5**
(مثلاً سيرفر مكسيكي تملكه)، ثم «اختبار وعرض IP». كل البث سيمر عبره. تفاصيل اختيار VPN في نهاية الملف.

> لا يتجاوز النظام حماية Cloudflare الأمنية؛ هو يوجّهك عبر VPN/بروكسي تختاره أنت (يحل الحظر الجغرافي، السبب الأشيع لـ 403).

## 🔐 الأمان والأدوار

| النقطة | المدير | العميل |
|---|---|---|
| إضافة/حذف مصادر IPTV | ✅ | 🚫 (403) |
| إدارة العملاء والإعدادات | ✅ | 🚫 (403) |
| مشاهدة المحتوى | ✅ | ✅ |
| رؤية بيانات المصادر/الإعدادات | ✅ | 🚫 |

- كلمات المرور مُجزّأة (scrypt + salt)، والجلسات موقّعة (HMAC) في كوكي HttpOnly.
- البث (`/proxy`) يتطلب جلسة مسجّلة؛ وحدّ الأجهزة يُفرض لكل عميل (الزائد يحصل على 429).
- ملف `config.json` يحوي بيانات حساسة (كلمات مرور مُجزّأة، اشتراكات) — **غير مرفوع إلى Git**.
